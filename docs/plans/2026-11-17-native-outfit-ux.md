# iOS 原生穿搭体验优化方案

日期：2026-11-17。产品：衣然 Aidrobe。实现以现有 SwiftUI iOS 26 客户端为基础，延续暖纸底、宋体标题、系统字体和原生玻璃控件。

这轮的核心是让用户始终知道“正在改哪一套、什么已经生效、接下来可以做什么”。同一套真实衣物可以在今日、对话、收藏和旅行之间继续使用，但每个会话、日期和收藏仍保留各自身份，不能被一个全局“当前搭配”覆盖。

## 1. 从后端能力到日常体验

代码基线为 iOS 草稿 #25 `4d6d1d1b302e78f2420221b689ce48cb4ccc99d4` 与后端草稿 #204 `c56a0726b158dcdd7353418c8c628e5c28260967`。两者在本轮核验时都未合并。用户指定的 Mac iOS 目录停在较早修复分支，因此不能把该目录或模拟器安装包当作最新功能全集。

| 已有能力 | 用户应感受到的变化 | 界面重点 |
| --- | --- | --- |
| 持久化会话与不可变 Outfit 版本 | 修改可以接着来，已经满意的部分保持 | 当前搭配可随时打开，历史保持独立 |
| 设计要求与已生成结果分离 | 要求被记住，但没有完成的结果不会冒充已更新 | 新条件、上一套、重搭操作分别清楚 |
| 保留、排除、局部换件 | “裤子留着”可以真的做到 | 单品操作使用原生 Menu 和现有替换 Sheet |
| 收藏列表与从原 Outfit 继续设计 | 过几天找到喜欢的一套，还能继续调整 | 详情首屏即可继续，不被明细挡住 |
| 本次探索与长期偏好分开 | 可以尝试新颜色，不必被旧风格锁住 | “这次试试”的范围清楚 |
| 灵感、旅行、穿着感受与方案衔接 | 不重复输入已经说过的条件 | 在有关场景出现，避免每套都堆满入口 |
| 天气核验、失败原因与工具记录 | 知道建议依据，失败能接着处理 | 简短结果依据与近端重试，不展示工具参数 |

收藏回看已经在 #25/#204 实现。本轮提升其发现、阅读和复用效率，不重新建一套收藏系统。

## 2. 信息架构

继续使用四个原生 Tab：今日、衣橱、问问、我的。每栏维持自己的 NavigationStack。

- 今日负责快速看穿搭、换件以及记录实际穿着。
- 衣橱负责真实单品和可穿状态。
- 问问负责围绕同一方案协作，包括局部修改、灵感和旅行衔接。
- 我的保留收藏、穿搭日记、偏好与设置。

原型中“阿然”是候选称呼，正式代码保留现有“问问”，直到角色命名被明确选定。拟人感优先来自行为：记得要保留的单品、区分一次尝试和长期偏好、失败后接着处理。

未来可以在衣橱内增加同一收藏列表的快捷入口；本轮不迁移全部日记、灵感和设置，不增加第五个 Tab，也不复制数据。

## 3. 三张原型表达的主流程

### 今日穿搭

首屏应依次呈现日期和场景、整套衣物、简短理由、主要动作。天气是轻量条件和页面光线，不做大天气卡片。单品明细和详细依据通过原生 DisclosureGroup 展开。

整套图与“看单品”使用原生 segmented Picker。生成摄影图是一张整体图片，不假设能精确点击其中每件衣服；切到单品视图后仍使用现有换件操作。

原型的“选这套”表达选定计划。当前客户端的 Today 主动作实际调用 markWorn，因此本轮正式文案改为“今天穿了这套”，明确记录真实穿着。问问的“放到今日/安排某天”继续承担采用方案的语义，收藏保持独立。

### 围绕这一套继续修改

当前方案前置到聊天历史之前，使用 DisclosureGroup 展开。输入框上方保留一个小入口，用户读长对话时也能直接回到当前方案。开始输入时收起大图，给键盘和聊天留空间；回复到达不强制把用户从正在阅读的历史拉走。

收到“裤子留着，上衣换成蓝色”时：

1. 新要求作为待应用条件呈现。
2. 旧图明确标为上一套。
3. 用户可直接点“按这些要求重搭”。
4. 该动作复用现有 ask 请求、会话、预期版本和幂等保护。
5. 生成完成后再允许采用新方案。

采用动作紧跟主图。出行打包、穿着感受、收藏与相关低频操作放入原生 Menu，功能继续可达。解释和条件放入原生折叠区，主图和决定先于长文本。

### 收藏穿搭复用

用户应先认出原来的那套，再决定是否继续修改。

详情先显示标题和整套图，已有生成图可直接读取；没有时使用原单品板。解释在图后，单品列表折叠。“从这套继续聊”通过 safeAreaBar 固定在底部，保留原生 glassProminent 风格。

继续设计仍携带确切 Outfit 身份。原收藏不因后续换件而被悄悄改写。这里的承诺是“从这套继续聊”，不是一定恢复当时的原对话。

## 4. 状态和动作必须对应

| 状态 | 文案与表现 | 可执行动作 |
| --- | --- | --- |
| 可用搭配 | 当前这一套 | 采用、换件、收藏 |
| 条件已变、方案未变 | 待应用的新条件；上一套 | 按这些要求重搭 |
| 请求执行中 | 正在处理的真实不确定状态 | 不重复提交；保留已有内容 |
| 结果未确认或版本冲突 | 保留输入和原方案，说明需恢复 | 沿用现有读取/重试机制 |
| 采用成功 | 已放到今日，或已安排到某日 | 不自动记录实际穿着 |
| 收藏成功 | 收藏这一不可变搭配 | 可查看、取消、继续设计 |
| 实际穿过 | 已记录穿着 | 再提供穿着感受 |
| 图片未生成或失败 | 原单品板继续可用 | 仍可看衣服、选择和换件 |
| 新图处理中、已有旧图 | 保留旧图并显示真实 ProgressView | 切换查看；禁止重复图像任务 |

现有 ask 接口返回完成后的结果，工具记录是事后证据。不要按计时器伪造“查天气完成、筛选衣服 60%”等实时进度。若以后需要真实分阶段反馈，应先有相应服务端事件或轮询契约。

## 5. 原生组件与视觉规则

| 目的 | 实现基础 |
| --- | --- |
| 一级导航 | 现有 TabView / Tab |
| 页面层级 | NavigationStack |
| 换件、反馈等局部任务 | 现有原生 Sheet |
| 低频动作 | Menu |
| 详情与依据收纳 | DisclosureGroup |
| 整套图和单品切换 | Picker + segmented |
| 主要操作 | .glassProminent |
| 次级浮动操作 | .glass |
| 底部可达操作 | safeAreaBar |
| 等待反馈 | ProgressView |

保留 `#FAF7F0` 暖纸背景、`#1A1714` 正文、`#B08D5B` 强调色，沿用 Theme.swift 的间距和字号。设计稿中的深色示意按钮不替换原生玻璃按钮。不会把屏幕做成网页或自绘一套导航和控件。

交互目标为舒适的触控尺寸，正文支持系统字级。长中文不依赖单行裁切表达关键状态；重要状态不只靠颜色；长按、滑动不能成为唯一操作入口。深色、大字号、键盘与 Reduced Motion 的实际表现仍需原生运行验收。

## 6. 整套图为什么需要改 prompt

当前确实有两条不同链路：

- 普通拼图：固定槽位把单件图贴到画布上。
- 生成整套图：每件衣服作为独立参考，通过多图编辑生成，再核对真实衣物。

生成模式已经逐件传入参考，并非必须先将衣物拼成一张图。现有 render_outfit prompt 很重视颜色、织物、接缝、鞋子和标记保真，但摄影构图要求较少。自然平铺摄影需要把“怎样摆、怎样拍”说清楚。

本轮摄影方向：

> 从正上方拍摄同一套真实衣物。使用暖象牙色哑光底和柔和窗光，保持中性白平衡。衣物比例真实，袖子和裤腿自然放置，有合理布料褶皱和接触阴影。构图有主次和留白，避免固定网格、独立商品框和剪贴边缘。仅允许不遮挡识别细节的适度重叠。所有衣服必须来自参考，保留颜色、面料、结构、左右方向与鞋子细节，不添加人物、道具或其他衣物。

原型里的衣物是示例生成素材，没有证明生产模型已能同样准确地还原用户实物。实际效果要用同一批真实单品作前后对照。摄影美感不能覆盖商品身份核验。

本轮保留原有模型、quality、size、配额与审核。单件商品图的 extract prompt 不改成生活摄影风格，避免破坏单品图用途。是否提高整套图质量档，应由真实小样评估决定。

### 缓存和历史图片

新摄影生成使用 `gpt-reviewed-v8`。新请求与跨 Outfit 复用都只匹配 v8，确保旧缓存不会掩盖 prompt 的变化。

已通过审核的 v7 继续可读，不因为风格版本较旧而被误标为质量失败。更旧或未知版本不自动放行，质量拒绝的图片仍不暴露 URL。

“获取最新整套图”表示取得当前服务版本：已有旧 v7 时可创建新版 v8，已有成功 v8 时会复用，不承诺每次生成一张随机新图。强制随机换图需要单独契约，本轮不添加。

鞋子质量审核改为按图片中实际位置检查，避免把“鞋一定在图片底部”的旧布局假设带入新摄影。真实细节审核保持不变。

## 7. 完整产品方向中的后续工作

以下是设计建议，未因这轮 UI 改动自动完成：

- 尝试新风格：从保留熟悉单品、只换一个变量开始；“这次试试”不自动修改长期偏好。
- 长期记忆：以自然语言展示来源和范围，允许纠错和忘掉；不要把内部权重暴露给用户。
- 灵感：图片详情的自然下一步是“用我的衣服搭一套”，参考图保留可见来源。
- 旅行：从已有方案承接行程，区分每天穿什么与要带什么；不假定所有自然语言编辑清单都已支持。
- 购物：围绕真实衣橱解释复用和缺口，判断结果保留；真人试穿仍需真实服务能力，不能以概念图代替。
- 穿后反馈：区分喜欢图、实际舒服和场景是否合适，允许纠正，不让一次跳过直接变成永久风格禁令。

## 8. 本轮代码与验收

iOS 修改集中在 AskView、TodayView、FavoriteOutfitsView 与已有 WalkthroughTests；不新增依赖、不改导航框架。后端修改集中在整套摄影 prompt、图片版本读取/复用和鞋审核提示，并补缓存与质量门回归。

必要验收场景：

1. 连续对话十轮后，不翻历史即可打开当前方案；回复不抢正在阅读的位置。
2. 新要求尚未生成时，旧图不会被误认为已更新；可直接触发重搭。
3. 打字、键盘展开、大字号时，方案入口和输入区仍可操作。
4. 从收藏换一件后，原收藏的单品组合保持。
5. 采用明天的方案不会写成今天实际穿过。
6. 原图、整套图、无图、质量拒绝和网络失败都保留可用路径。
7. 旧 v7 可读，新 POST 生成 v8，重复请求不建重复任务。
8. 更旧/未知版本与质量拒绝图不会因兼容逻辑被展示。

iOS 合并门槛为既有 AidrobeKit 单元测试、模拟器目标编译与契约校验；后端遵守 AGENTS 的 CI-only 要求。构建成功不能替代视觉和真实摄影质量验收。

本轮 Mac 授信已从只读变为工作区可写，但 Git 元数据与 CoreSimulator 系统服务仍被执行环境隔离。代码通过独立 GitHub 分支审阅和 CI 验证，不能宣称已安装到本机模拟器。
